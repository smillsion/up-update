# 使用指南

[返回首页](../README.md) · [部署指南](DEPLOYMENT.md) · [配置说明](CONFIGURATION.md)

本文面向管理员和普通用户，介绍从首次登录到接收 Bark 推送的完整流程。

## 首次登录

部署完成后，打开服务地址，在项目主页点击“登录系统”，使用 `.env` 中的 `UP_UPDATE_ADMIN_USERNAME` 和 `UP_UPDATE_ADMIN_PASSWORD` 登录。

管理员账号只会在空数据库首次启动时创建。数据库中已有用户后，修改 `.env` 不会重置管理员用户名或密码。

## 管理用户

管理员进入“管理”页面，可以：

- 创建普通用户
- 设置显示名称和临时密码
- 停用或重新启用用户
- 重置普通用户密码
- 永久删除普通用户及其个人数据
- 查看用户的订阅数量以及 B 站、Bark 配置状态

用户名需要包含 3–32 个字母、数字、下划线、点或短横线；临时密码至少 10 个字符。普通用户首次登录后必须修改临时密码。

停用用户后，该用户无法登录，其订阅也不会参与轮询和投递。

永久删除会清除该用户的登录会话、B 站与 Bark 配置、订阅和通知记录，且无法恢复。删除前必须输入目标用户名确认。管理员账号不能被删除；其他用户仍在使用或通知历史仍在引用的 UP 主和视频数据不会受到影响。

## 登录 B 站

B 站登录是可选功能。通过 UID 或空间链接添加订阅、后台检查公开投稿都不需要 Cookie；只有从当前账号的关注列表批量导入时才需要登录。每位用户使用自己的 B 站账号，不与其他用户共享 Cookie。

### 扫码登录

需要从关注列表导入时，推荐使用扫码登录：

1. 进入“设置”。
2. 在“B 站登录”区域点击“扫码登录”。
3. 使用哔哩哔哩客户端扫描二维码。
4. 在手机上确认登录。
5. 页面显示账号名称和“自动续期”后即完成。

扫码成功后，系统会加密保存 Cookie 和刷新令牌。后台定期检查登录状态，并在 B 站要求刷新时自动更新凭证。

自动续期不能绕过 B 站账号安全策略。主动退出账号、修改密码、账号风控或服务器撤销会话后，仍需重新扫码。

需要解除绑定时，可以在“设置”中点击“退出 B 站账号”。该操作只删除 up-update 本地加密保存的 Cookie 和刷新令牌，不会退出手机或浏览器中的 B 站账号，也不会删除已有订阅和通知历史。

### 手工 Cookie

无法扫码时，可在“设置”中展开“手动填写 Cookie”。手工 Cookie 没有配套刷新令牌，不支持自动续期。

推荐使用电脑上的 Chrome 或 Edge 获取完整 Cookie：

1. 打开 [哔哩哔哩网页版](https://www.bilibili.com/)并登录。
2. 按 `F12`，进入“网络（Network）”。
3. 过滤 `x/web-interface/nav` 并刷新页面。
4. 打开 `https://api.bilibili.com/x/web-interface/nav` 请求。
5. 在“标头（Headers）”的“请求标头（Request Headers）”中找到 `cookie`。
6. 复制 `cookie:` 后面的完整内容，粘贴到 up-update 并验证保存。

完整 Cookie 通常包含：

```text
SESSDATA=...; bili_jct=...; DedeUserID=...
```

不要使用 `document.cookie` 作为首选方式，它可能无法读取带有 `HttpOnly` 属性的登录 Cookie。不要修改 `%2C`、`%2F` 等编码，也不要将 Cookie 发到聊天、截图、Issue、日志或 Git 仓库。

## 配置 Bark

1. 在 iPhone 上打开 Bark，复制 Device Key。
2. 进入 up-update 的“设置”。
3. Bark Server 使用官方 `https://api.day.app`，或填写自己的 Bark Server 地址。
4. 填写 Device Key、通知级别和提示音。
5. 点击“发送测试”，确认手机收到通知。
6. 点击“保存 Bark”。

已保存 Device Key 后，修改其他 Bark 设置不需要再次填写。测试推送使用页面当前值但不会自动保存，也不受睡眠或午休延迟影响。

### 通知级别

| 级别 | 用途 |
| --- | --- |
| 主动通知 | 默认方式，正常显示声音和横幅 |
| 时效性通知 | 适合希望更及时看到的更新 |
| 静默通知 | 降低打扰，不主动发出提示音 |
| 重要警报 | 需要 Bark 和 iOS 具备相应权限，谨慎使用 |

提示音支持 `alarm`、`bell`、`chime`、`electronic`、`glass`、`minuet`、`newsflash`、`update`，也可以填写 Bark 支持的自定义名称。

### 午休延迟补发

每位用户可以独立开启午休延迟补发，默认时段为 `12:00–14:00`。时段内检测到的新视频会进入等待发送状态，结束后按队列逐条补发。

如果午休时段与管理员设置的睡眠时段重叠，通知会延迟到两个时段都结束后再发送。

## 添加订阅

进入“UP 主订阅”页面，可以使用以下任一方式添加：

- 纯数字 UID，例如 `546195`
- UP 主空间链接，例如 `https://space.bilibili.com/546195`
- 点击“从关注导入”，从当前 B 站账号的关注列表选择

关注列表支持分页浏览，每次最多选择 20 个账号。已经订阅的账号会被标记并跳过。

新增订阅会把当前最新投稿作为基线，不会发送旧视频。批量导入时若个别 UP 主初始化失败，订阅仍会创建，并由后台继续获取最新投稿。

订阅列表中可以：

- 暂停或恢复单个订阅
- 查看最近投稿、具体投稿时间、距今时长和上次检查时间
- 点击标题打开视频
- 删除不再需要的订阅

## 分时轮询与通知

管理员在“管理”页面配置全局分时轮询：

- 睡眠模式：降低轮询频率，并延迟自动通知
- 工作模式：使用工作时段对应的检查间隔
- 空闲模式：在其他时间使用空闲间隔

完整规则和范围见[配置说明](CONFIGURATION.md#分时轮询)。

检测到新视频后，系统为所有启用该 UP 主订阅且已配置 Bark 的用户创建独立投递。点击 Bark 通知会直接打开对应视频。

接口或网络失败时系统会自动退避，Bark 投递失败也会重试，因此实际通知时间可能晚于视频发布时间。

## 通知记录

“通知”页面按时间分页展示投递记录：

| 状态 | 含义 |
| --- | --- |
| 等待发送 | 正在等待投递，或处于睡眠、午休延迟时段 |
| 已送达 | Bark Server 已接受推送请求 |
| 发送失败 | 达到重试条件后仍未成功，页面会显示错误信息 |

等待发送的通知可以手动取消。已经送达或失败的历史记录不能从页面删除。

## 修改密码

普通用户首次登录必须修改临时密码。之后可在“设置”底部进入“修改登录密码”。管理员为用户重置密码后，该用户现有会话会失效，并在下次登录时再次要求修改临时密码。

## 常见问题

### 从关注导入按钮不可用

从关注列表导入需要有效的 B 站登录，请进入“设置”扫码登录。UID 和空间链接订阅不受影响，可直接点击“添加”。

### UP 主检查时间没有同时更新

每个 UP 主独立调度，检查时间会错开。订阅页面不会持续自动刷新，可点击右上角刷新按钮查看最新状态。

### 新视频没有立即推送

依次检查：

1. 订阅是否启用。
2. 订阅卡片是否显示 B 站匿名访问风控或网络错误。
3. Bark 测试是否成功。
4. 当前是否处于睡眠或午休延迟时段。
5. “通知”页面是否显示等待发送或失败原因。

### Bark 测试成功但自动通知延迟

测试推送不会受延迟时段影响，自动通知会遵循管理员睡眠时间和用户午休设置。这是预期行为。
